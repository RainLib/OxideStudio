# JSON / JSONL 有界导入

G08 的本批增量将普通 JSON 对象/数组与 JSONL/NDJSON 接入同一条有界解析、预检、类型推断和事务写入路径。文件上限是 512 MiB，执行前不再保留完整记录数组；XLSX 也已接入同一批次/事务路径，见 [XLSX 有界导入](STREAMING_XLSX_IMPORTS.md)。后续新增的 SQLite 文件任务及逐行默认值语义见下文。**G08 尚未完成：桌面准备/任务接线、历史规模与其他平台验收、更多数据库及显式跳过坏行策略仍待实现。**

## 当前执行契约

1. 沿用现有目标权限、连接/数据库选择、源摘要复核及参数化行写入。源摘要读取与 JSON 预检在阻塞工作线程中执行；不在 Tokio 命令线程上解析完整文件。
2. 解析工作线程最多预先排队两个批次。每批最多 500 行、完整行 JSON 编码合计不超过 2 MiB；接收端较慢时解析暂停，接收端关闭时停止解析，普通 JSON 读取期间每约 8 KiB 检查取消。
3. 写入使用单一显式数据库事务。Append 追加；Truncate 使用事务内 DELETE，首批也未提前提交。解析尾部错误、字段/值校验错误、数据库约束错误或显式取消都走回滚。只有解析工作线程正常结束、完整文档通过尾部校验且未取消，才提交事务。
4. 运行中的行数表示当前事务已执行的行数；终态成功才表示提交。保留既有终态报告，不把进度事件当作可恢复游标或已提交分段。

## 资源与输入边界

| 范围 | 当前约束 |
| --- | --- |
| 文件 | JSON/JSONL/NDJSON 最多 512 MiB；读取过程中同样累计检查字节数，文件增长不能绕过上限。 |
| 单条记录 | 原始记录跨度最多 1 MiB，包含相关空白/分隔符；JSONL 包含换行。限制在读取/解码时生效，不在整条超长值分配后才检查。 |
| 字段 | 每条最多 256 个顶层字段，字段名最多 256 UTF-8 字节；重复的顶层字段明确拒绝。类型推断和预览的列集合也最多 256 项。 |
| 队列/批次 | 最多两个等待批次，每批最多 500 行和 2 MiB 行 JSON；序列化临时值、字段容器、当前解析行和数据库参数另外占用内存。不是进程 RSS 上限。 |
| 预览 | 最多 50 个样本，样本行 JSON 合计最多 2 MiB；保留原有嵌套值/字符串缩略。达到字节预算也标记 truncated，列元数据和响应封装另占空间。 |
| 预检 | 扫描全部记录并给出 accepted/rejected 总数，最多展示 100 条稳定的行号/分类诊断，不返回源值。它校验映射和行参数，不预先证明数据库唯一键、外键等约束一定成功。 |
| 事务 | JSON 类文件不再使用物化数组的 100,000 行限制。单一事务仍受具体引擎的日志、锁、磁盘和权限约束；不以加大文件上限替代这些限制。 |

JSON 对象、对象数组和逐行对象均使用严格 JSON 解析。尾随的第二个文档或非空数据、非对象数组元素、重复顶层字段和超长记录都拒绝；不存在忽略坏行后默默提交部分数据的分支。预览可以只展示 JSONL 前部样本，完整预检与实际写入仍独立校验后续内容。

源摘要是在复核时读取的；当前没有为所有导入建立持久不可变快照，也不保证外部程序并发改写源文件时得到同一时点视图。原生验收的“源不变”证明导入没有修改夹具源文件，不代替并发改写验收。进程退出/崩溃后的任务发现、重试与去重仍属于尚待实现的持久导入协议。

## SQLite 可恢复文件任务

新增 `prepare_table_import_job` / `list_table_import_jobs` 与 `fileImportJobService`，准备 CSV、JSON/JSONL/NDJSON 或 XLSX 的私有快照。当前仅原生、本地、已保存且属于当前项目的 SQLite 目标；不将文件伪装成保存的数据库连接，也不绕过外置包选择。普通 `import_table_data` 仍是默认单一事务入口。

### 准备、审阅与恢复

1. 准备必须提供审阅时的完整源 SHA-256。复制源文件时累计检查 512 MiB、计算摘要并检查取消；后续解析只读这份私有副本。摘要不符拒绝，外部源在复制期间改变不能用后续重读来替换已审阅的内容。
2. 保留既有 CSV 编码、标题/起止记录、按位置忽略/重命名、空串转 null 和 trim 规则；JSON/XLSX 使用现有原生解析器。标题/字段集合最多 512 项，JSON 自身仍最多 256。归一化写入私有 SQLite `data` 表，每行另有 Host 生成的稳定顺序键，整数、实数、文本和嵌套 JSON 文本不通过 renderer 往返。
3. 固定映射最多 512 列；单行使用迁移执行器的 1 MiB 预算，包含每字段预留开销，预读最多两个批次、每批 500 行/2 MiB。CSV 记录在解码读取时限制约 1 MiB（另有最多 8 KiB 预读），解码累计最多 2 GiB；归一化数据库限制为 4096 字节页、524288 页。私有源、归一化数据库、持久快照、目标暂存和日志分别占盘，不是整台机器或多任务的总磁盘/内存上限。
4. 固定列集合任务使用账本 v4；JSON 逐行列集合不同或全部行为空对象时使用 v5，另存 Host 的字段存在位图。格式、文件名、源/归一化摘要、映射、选项及位图列元数据均认证到审阅摘要；位图值与业务值一起进入每批回执摘要。缺省位图字段不改变既有 v1–v4 的序列化/MAC。普通迁移与文件导入的历史查询分开分页。公开映射只列业务字段，不把内部位图写入目标表。
5. 准备仅返回 `IMPORT …` 确认短语，不自动开始写入。确认后复用迁移引擎的 OS 租约、目标暂存、已提交批次回执与游标。暂停/进程终止后恢复时重新核对原目标身份、保存连接、结构、内容、快照和回执；原始文件及临时归一化输入此时均可离线。已确认批次不会再次插入。
6. 发布前目标行保持不变。Append 全部插入；Truncate 对应显式审阅的 Overwrite，在一个事务内 DELETE 后发布，触发器/约束失败回滚。发布完成的目标回执用于恢复“目标已提交、主账本尚未更新”的窗口。成功/取消清理持久快照，目标保留小型完成回执。目标变更和认证失败要求重新审阅，不能静默重新路由或清零游标。

### 保真边界与未完成项

- 全局未映射列仍由目标默认值处理。v5 区分逐行省略、显式 null 与已提供值：位图为零的字段保持暂存 null，但发布的 INSERT 列表中省略该字段，由目标在发布事务内执行默认表达式；显式 null 仍按 null 写入，不替换成默认值。全部为空对象的 JSON 可生成 DEFAULT VALUES 行，前提是既有必填字段验证允许省略。准备/暂存不执行默认表达式。
- JSON 列名按既有 trim/ASCII 大小写规则逐行映射；不同行中的 `ID`、`id` 和 ` id ` 可映射同一目标，同一行中重复映射仍拒绝。审阅列保留该目标首次遇到的源标签，完整源摘要绑定所有原始键和值。存在位按规范化后的目标列集合定义，避免别名把省略/null 混淆。
- v5 按源顺序逐行发布，保留有界的最后一个列集合缓存，不积累任意数量的字段组合。每次先读取最多 500 个行大小，再取最多 4 MiB 的值窗口；位图最多 64 B，长度、未用位及“省略字段不得藏有非空值”再次检查。覆盖删除、已写前序行、默认值/触发器/约束失败均处于同一发布事务中；位图篡改同样使回执核对失败。固定形状 v4 保留原批量发布路径。
- 本适配器的精确原生整数范围是 i64；新快照和普通 SQLite 参数化入口都拒绝更大的 u64，避免转负数或经浮点舍入。普通参数化批次同时改用有生命周期的事务，并在参数绑定或 SQL 执行失败时显式回滚，避免后续绑定错误留下前面尚未提交的写入。回归保留 i64 两端与 9007199254740993 的精确往返，确认 u64::MAX 被拒绝且失败批次的前序行也撤销。原始 XLSX 保存之前已损失的精度无法恢复。日期样式与缓存公式维持现有解析契约。
- 原生准备任务已新增 v2 持久定义和归一化事务游标，详情见下文。旧 v1 工作目录仍按无活动 lease 的认证归属规则回收；v2 输入保留，等待显式恢复/丢弃。尚未接入导入对话框、任务卡和多任务聚合预算；目标绑定与就绪交接已增加 v6 协议，实际桌面和历史规模等边界仍待补齐，不能描述成完整桌面交付。
- PostgreSQL/MySQL 等导入目标、显式跳过坏行策略、更多生产者/布局及平台继续实施；不以已有迁移适配器代替文件导入逐项验收。

复验：`node scripts/test-resumable-import.mjs`。脚本创建真实百万行 JSON，完成生产复制/解析/归一化/审阅，在真实已提交批次出现且目标仍为空时终止自己启动的进程；把原始文件移到离线路径，启动新进程从持久账本恢复，逐键核对全部值、默认值、摘要及唯一性。初始进程的故意终止不算普通测试通过，恢复进程必须正常退出且测试通过。内存分别采集初始与恢复进程，原始大文件和目标数据库只在二者退出后按已核对边界删除；不上传私有账本/认证密钥或大夹具。

`prepare_table_import_job` 现在使用 `begin_resumable_file_import_preparation`。认证 `intent.json` 绑定准备 UUID、项目和完整请求，包括源路径/摘要、格式、选项、目标及审阅时的列元数据，不保存连接凭据或源行。定义 body 上限 512 KiB、编码 envelope 上限 1 MiB；原有 `owner.json` 保持 8 KiB 预算，绑定定义 MAC。v1 记录省略新增可选字段，保持其认证编码兼容。

- **原生边界**：数据库只允许精确的 data/游标表定义，拒绝新增 trigger/view/index；读取 schema 最多三条，游标 body 最多 512 KiB。打开后在独占 SQLx handle guard 内把 `SQLITE_LIMIT_LENGTH` 限为 4 MiB，限制 SQLite 自身的大值分配，而非只限制 Rust 队列。恢复入口重新校验当前目标列元数据与保存定义；全部解析/复核成功后才创建就绪审阅，目标发布继续使用原 v4/v5 任务协议和确认令牌。

### 文件导入界面与恢复入口

CSV、JSON、XLSX 原生预览新增 **Prepare resumable…**，普通单次导入仍保留。入口仅对已保存的本地原生 SQLite、可写且非执行中的表、具有已审阅摘要的原生文件出现；托管、外置包、SSH、其他驱动和浏览器文件不进入这条流程。请求固定项目、目标端点、格式、源摘要、选定写入模式、表头和 CSV 映射/编码/范围/空值设置，最终仍由原生边界重新验证。

CSV 准备直接发送原生文件路径和已选选项，不调用 worker 的完整 `rows()`。截断预览显示来源前缀说明，不能执行普通预览导入；可恢复准备会完整解析原生文件并在私有目录生成审阅，不把前端的 32 MiB/100,000 行审阅上限作为全源已验证的证明。

**Background Tasks → File imports** 打开项目作用域的独立任务窗口。左侧分别分页加载准备与就绪作业；同一 UUID 已交接时选择就绪记录。右侧显示文件/目标/写入模式、准备阶段、观察到的字节和行数；观察计数可能落后于事务游标，不显示虚构完成百分比。显示信息从认证 intent 投影，只返回源文件名，不返回完整源路径、行值或连接凭据。活动 lease 只允许取消准备；取消删除私有准备数据。非活动准备可以继续或丢弃；继续失败保留原记录，目标变化和旧绑定错误仍要求新审阅。关闭窗口不发取消命令，项目切换/关闭后到达的旧异步结果不写入新窗口。

准备成功只生成审阅，**不会自动开始发布**。已有文件任务复用现有目标、映射、警告和精确输入确认令牌，以及分批暂停/取消/续传。覆盖模式沿用目标全事务语义。完成后需要手动刷新表格；不会自动丢弃已有编辑草稿。文件作业目前从后台任务入口进入独立历史窗口，尚未投影到常驻任务摘要，也未提供系统完成提醒。

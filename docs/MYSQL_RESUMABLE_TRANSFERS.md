# MySQL 可恢复整表迁移

现有迁移对话框的 `Full transfer & saved jobs` 入口已接入 MySQL，沿用私有快照、审阅短语、暂停、取消和保存任务。原小任务的行数上限、建表、schema 恢复和 identity 开关不用于这条整表路径。

## 使用与范围

1. 在同一项目选择两个已保存的原生 MySQL 连接、一个源表和一个现有目标表，选择 append、overwrite 或主键 upsert。
2. 进入 `Full table transfer`，点击 `Prepare full snapshot`。准备需要读取源表，并扫描目标现有内容以绑定审阅；目标原有行不在此时修改。
3. 核对源/目标连接、数据库和表名、模式、行数、列类型与映射，输入本次短语再开始。暂停后恢复须重新输入；开始请求的响应丢失也不会保留之前输入的短语。
4. 关闭对话框不会停止当前应用内的作业。应用退出后停止执行；重开相同 profile 和项目可以恢复。快照完成后的续传不需要源连接路由在线。

当前要求原生 MySQL 8.0.22 或更高版本的 InnoDB 表、直接连接和已有目标表。MariaDB、TiDB、系统库、视图、多表、跨产品、SSH 和已选外置驱动包不走这条路径；后端也会再次验证，不会在外置包不可用时静默退回内置驱动。partial_revokes 已启用的服务器目前会被拒绝，不要求用户为此放宽服务器权限策略。

目标列先按精确名称匹配，再允许无歧义的大小写匹配。生成列明确跳过；普通源列未映射或有歧义会拒绝准备。必填目标列必须有映射、默认值或自动身份值。Upsert 需要映射完整的目标主键；其他唯一键冲突会回滚整次发布，不会改写另一个主键的行。

## 数据与资源

源只读事务流式读取所选表，写入本机私有 SQLite 快照。该文件包含所选表的明文业务值，暂停期间仍占磁盘；它不是整个 MySQL 数据库备份。整数、DECIMAL、UTF-8、二进制和浮点原始位不经过 JavaScript 数字转换；TIMESTAMP 快照使用 UTC，最终赋值保留微秒，并恢复目标正常连接的 sql_mode 和时区。

| 项目 | 当前约束 |
| --- | --- |
| 行与列 | 行帧最多 1 MiB、最多 512 列，超限拒绝而非截断。 |
| 批次 | 最多 1,000 行、4 MiB，并按实际 max_allowed_packet 和 prepared 参数数进一步缩小。 |
| 磁盘 | 本机快照、目标暂存日志、会话临时表、数据库事务日志可能同时占空间。 |
| 权限 | 源表读取及元数据可见；目标数据读写、创建/删除作业对象、CREATE TEMPORARY TABLES，以及目标和作业表的 TRIGGER 可见权限。 |
| 角色 | 已实测仅授予测试库权限的默认角色；未把它外推为全部角色、授权和 partial revokes 组合通过。MySQL 8.0.46 的转义库名授权限制见下文。 |
| 锁 | 最终发布完整锁定目标数据和插入范围；其他事务可能使其等待或暂停，需要恢复后重试。 |

目标列类型、精度、字符集、排序规则、空值和主键约束用于发布前的类型校验。不同类型或精度按目标转换规则处理，不承诺值完全相同；转换诊断会拒绝发布。默认值、生成列和目标触发器只在实际目标写入时应用。MySQL 原生 auto_increment 空洞、触发器对非事务对象或外部系统的副作用仍遵循 MySQL 自身语义。

本机 MySQL 8.0.46 中，默认角色通过转义下划线的库级 GRANT 获得权限时，原生认证选库及后续原生 USE 均返回 1044。应用同样拒绝准备，目标保持不变；普通库名的库级默认角色及撤销 TRIGGER 后的拒绝已通过。这与 [MySQL 缺陷库 #110582](https://bugs.mysql.com/bug.php?id=110582) 描述相似，但该报告状态为 Can't repeat，本项目以实际探针为依据，不推断全部 8.0 版本。此组合继续作为明确限制；不会自动扩大授权范围。

## 发布、恢复与取消

每批原始行与认证回执在目标同一 InnoDB 事务提交。本地 checkpoint 落后时按目标已提交事实恢复，拒绝缺失、篡改和不连续进度。最终目标修改、published 回执和暂存数据删除同事务提交；其中不执行会隐式提交的持久 DDL。完成后保留一条小回执。

目标服务器、表定义、触发器或既有内容改变时需要重新准备。原目标配置密封在本机认证账本中：保存的连接后来被编辑，也不会把完成核查或取消重定向到新目标。取消只清理能验证归属的暂存对象及本机快照；认证变化时保留对象并要求复核。取消请求仍在处理时不会提前开放恢复按钮。
